# Debounced inject for streamed/edited lines (mcp-absorb inject loops)

Context: mcp-absorb (this repo, src/main.rs) wraps an MCP server and runs "inject loops" that poll a tool and type fresh result lines into a tttt session. With a filter active (`set_inject_filter` patterns), lines without a pattern go to the backlog and never interrupt the session. Problem: one peer (Rusty, sender `rusty` on `[msgd #rusty]` lines) streams its progress as EDITS of one message; every poll yields a new line `[msgd #rusty] rusty: <current body>` (interim bodies usually end with the cursor mark U+258D `▍`; the final body has none). None contain a pattern, so the final reply never nudges the session; ayourtch wants: still notified, but throttled.

Add an optional per-loop debounce, set through the existing `set_inject_filter` tool (new optional integer arg `edit_debounce_secs`, default 0 = off, max 600) and shown by `list_tttt_inject_loops`:
- Semantics, per sender (use the existing `line_sender_and_body` split; for lines without a sender, behave as today): a line that the filter would NOT inject (no pattern, no follow/continuation match) becomes the sender's PENDING line, replacing any earlier pending line from that sender (the replaced one goes to the backlog as today). When no new line from that sender has arrived for `edit_debounce_secs`, inject the pending line (provenance-prefixed like any other inject) and clear it. Lines that the filter WOULD inject keep today's behaviour and also clear that sender's pending line (drop it to the backlog).
- Progress ping: while a sender keeps a pending line replaced for longer than 30 s continuously, inject one line at most every 30 s of the form `[<loop> debounce] <sender> still streaming (<n> edits, <secs> s)`; keep it terse. Constant PROGRESS_PING_SECS = 30.
- The pending check runs on every poll tick (the loop polls every few seconds; do not add a new timer thread unless the loop already has one), so the inject fires within one poll interval after quiescence.
- Filter OFF (no patterns) + debounce ON must also work: then EVERY line is subject to the debounce (all lines from a sender within the window collapse to the last one). Filter OFF + debounce OFF = today.
- `set_inject_filter` without `edit_debounce_secs` leaves the current debounce value unchanged; `edit_debounce_secs: 0` turns it off and flushes pending lines to the backlog. Update both tool descriptions (one sentence each).

Constraints: smallest change, no refactor, no renames, keep `filter_decide` pure (add the debounce as a step around it, e.g. a `Debounce` struct with `offer(sender, line, now) -> Option<String>` and `due(now) -> Vec<String>`). Tests: unit tests for the Debounce struct: (1) 3 lines from one sender at t=0,2,4 with window 5 -> nothing due until t=9, then exactly the t=4 line; (2) a pattern-matching line at t=3 clears the pending line (it is in the backlog, not injected later); (3) progress ping fires at t=30 and t=60 but not t=45 while lines keep coming; (4) window 0 = passthrough of today's behaviour. `cargo build --release` and `cargo test` must pass.
